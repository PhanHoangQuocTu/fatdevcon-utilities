@fatdevcon/utilities

@fatdevcon/utilities

Typed utilities for everyday JavaScript and TypeScript: exact decimal math that works on numbers, bigints and numeric strings of any practical size, locale-aware formatting, Unicode-safe text, arrays, objects, timing helpers and validators.

npm install @fatdevcon/utilities
import { summary, factorial, isPrime, formatCurrency, formatBytes } from "@fatdevcon/utilities";

summary(0.1, 0.2);                                // 0.3
summary("100000000000000000000000000000", "1");   // "100000000000000000000000000001"
factorial(25n);                                   // 15511210043330985984000000n
isPrime(2n ** 127n - 1n);                         // true
formatCurrency("12345678901234567890.129", "USD"); // "$12,345,678,901,234,567,890.13"
formatBytes("1500000000000000000000000000000");   // "1.5 QB"

Ships ESM and CommonJS builds with type definitions. Requires Node.js 18+ or Bun 1.1.34+ (Node 20+ to format bigint and string values with every digit). Functions never mutate the arrays or objects you pass in.

Big numbers

A JavaScript number is a 64-bit double: it carries about 16 significant digits, tops out near 1.8 × 10308 and cannot store 0.1 exactly. The numeric functions keep working past those limits when you give them a bigint or a numeric string, and they refuse, with a clear error, to hand back a wrong answer.

Use isNumeric to test a value first. In TypeScript the accepted union is exported as NumericInput.

What you get back

The return kind follows the input kind, so existing number code keeps returning numbers.

Strings are the safe way to carry big or decimal values between systems: JSON has no bigint, and a 20-digit id or amount parsed by JSON.parse is already rounded. Keep it as text and pass it straight in.

Precision and rounding

All arithmetic runs on decimal.js, never on binary floating point. The package uses private decimal.js instances, so it never touches the global decimal.js configuration of an application that also uses the library, and that configuration never affects it. Addition, subtraction, multiplication, modulo and integer powers are exact. Division is exact when the quotient terminates and otherwise keeps precision significant digits (1 to 10000, default 40), rounding half up. Converting an exact result back to a number rounds once, to the nearest double. Decimal inputs are read the way they are written (0.1 is one tenth, not 0.1000000000000000055…), which is why round(1.005, 2) is 1.01.

Speed

Whole numbers take a native fast path: calls on safe integers never build a decimal object, and sumValueInArray adds a million integers in about 40 ms (a million fractions take about 0.4 s). factorial(65000n) and fibonacci(1000000n) finish well under 0.2 s on Node and Bun, and a 521-bit isPrime takes about 10 ms. Intl.NumberFormat instances are cached per locale and option set. The limits above are identical on every runtime: JavaScriptCore (Bun, Safari) caps a BigInt near 220 bits, so the package stays inside that on purpose.

Error handling

Invalid input throws a standard error instead of returning NaN or a wrong result. Numeric errors are NumericTypeError (extends TypeError) or NumericRangeError (extends RangeError) and carry a stable code, so instanceof TypeError and instanceof RangeError keep working while you can branch on the exact reason. Messages name the argument and show the offending value, for example a must be a finite number, bigint or numeric string, received "12abc".

ERR_OUT_OF_RANGERangeErrorAn argument is outside its supported rangefactorial(171), clamp(1, 5, 0), round(1, -1), formatBytes(-1)

Non-numeric argument mistakes (a non-array, a non-function callback, a non-string text) throw a plain TypeError or RangeError without a code.

import { divide, NumericRangeError } from "@fatdevcon/utilities";

try {
  const share = divide(total, count);
} catch (error) {
  if (error instanceof NumericRangeError && error.code === "ERR_DIVISION_BY_ZERO") {
    // count was 0
  } else {
    throw error;
  }
}

Types

import type {
  NumericInput, DivideOptions, RoundingMode, NumericErrorCode,
  Comparator, KeySelector,
} from "@fatdevcon/utilities";

type NumericInput = number | bigint | string;
type RoundingMode = "half-up" | "half-down" | "half-even" | "up" | "down" | "ceil" | "floor";
interface DivideOptions { precision?: number } // significant digits, 1 to 10000, default 40
type NumericErrorCode =
  | "ERR_INVALID_NUMBER" | "ERR_NOT_INTEGER" | "ERR_DIVISION_BY_ZERO"
  | "ERR_OVERFLOW" | "ERR_UNDERFLOW" | "ERR_OUT_OF_RANGE" | "ERR_PRECISION_LOSS";

// Negative, zero or positive, like Array.prototype.sort
type Comparator<T> = (a: T, b: T) => number;
type KeySelector<T> = (item: T) => any;

The error classes NumericTypeError and NumericRangeError are exported as values. Option types are exported too: CompactNumberOptions, PercentFormatOptions, CurrencyFormatOptions, UnitFormatOptions, BytesFormatOptions, TruncateTextOptions, ShortenStringOptions, MaskStringOptions, RelativeTimeOptions, DurationOptions, DebounceOptions, ThrottleOptions, MemoizeOptions, RetryOptions, IsUrlOptions.
